02 · Who does what

How the work is split

One root daemon holds the state and spawns small threads for each job. Each VM is a separate Firecracker process. The Linux kernel and Nginx do the packet work.

process · root

cryospawn daemon

HTTP server httplib · :8080
Runs each REST handler and serves the dashboard files.
configure_and_start 1 per create
Detached thread that configures Firecracker and boots the guest.
Reaper 1 · every 2 s
waitpid() + kill(pid, 0); cleans up dead VMs and keeps hibernated or restarting ones.
VMManager mutex shared
Serialises changes to the in-memory VM map and their SQLite writes.
threads inside the daemon

Ghost Proxy

Listener 1 per exposed port
Owns /tmp/cryo_vm_N_P.sock (chmod 0666) and loops on accept().
Client handler 1 per connection
Wakes the VM if it is hibernated, then connects to guest IP:port.
Relays 2 per connection
relay_data() copies bytes in each direction with an 8 KB buffer.
process · 1 per live VM

Firecracker

MicroVM KVM guest
Started with fork() + execlp and setsid(), so stopping the daemon does not kill it.
API socket /tmp/cryo_N.socket
The daemon configures it with PUT/PATCH: boot source, drives, NIC, machine config, snapshots.
Hibernated 0 processes
The process is killed; the VM lives on only as .snap and .ram files.
Linux kernel

TAP + netfilter

TAP cryoN 1 per VM
Point-to-point /30 link between the host gateway and the guest.
iptables baseline + links
NAT to the internet, DROP between VMs, 4 extra rules per link.
process · host

Nginx ingress

vmN.cryo :80 and :443
A regex captures N from the host name and proxies to that VM's Unix socket.
/etc/hosts 127.0.0.1
Points vmN.cryo names at the local machine.
files

State on disk

cryospawn.db SQLite
Tables vms, network_links and volumes; read again on every startup.
instances/ per VM
Its own copy of the rootfs, plus snapshot files while it is hibernated.
volumes/ vol_N.ext4
Extra ext4 disks attached as additional Firecracker drives.
